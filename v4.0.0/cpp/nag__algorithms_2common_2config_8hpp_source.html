123 // These are the SLICE-moving tracking tolerances (Bertini 1's SliceTol* family) -- the tolerances
124 // for moving the linear slices during regeneration, kept separate from the main tracking
125 // tolerances in TolerancesConfig. The slice_ prefix makes every config field name unique across
126 // structs, which is what lets a field be set on an owner without naming its struct
127 // (owner.update(field=...) routes by field).
128 // Defaulted to the same values as the main tracking tolerances they shadow (TolerancesConfig),
129 // which is where Bertini 1 takes its SliceTol* defaults from. They were uninitialized, so a
130 // default-constructed config read indeterminate memory and had no default to document (b2#406).
131 // Regeneration is scaffolding today, so nothing computes differently for this.

201// Not templated on the complex type: the three times are stored as exact, precision-free
202// mpq_rational (real) and converted to the tracking complex type at the current working precision at
203// use -- the same pattern SteppingConfig uses for its step sizes. This keeps the config precision-
204// agnostic (one struct, not a DoublePrec/Multiprec pair), and is in fact more correct under adaptive
205// precision: a value like the endgame boundary 1/10 is materialized at full working precision rather
206// than frozen at whatever precision the config happened to be constructed at.
